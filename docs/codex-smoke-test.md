# Codex 检查清单

这是执行方法，不是通过记录。分别记录环境、版本、日期、命令、结果和未完成项；
正式版实际结果写入 `validation-v1.0.0.md`。

## 默认文字安装

用临时目录检查安装，避免修改正在使用的技能：

```bash
promotion_test_dir="$(mktemp -d)"
bash tools/install_codex.sh --dest "$promotion_test_dir/skills"
```

| 检查 | 操作与应观察的行为 |
|---|---|
| 基础环境 | 只要求基础 shell 与 Python 3；未选择 Word 时，不因缺少 Node、文档转换工具或字体而阻断文字安装 |
| 默认范围 | 只安装 `promotion-master`，包内参考完整，主入口不依赖额外专项技能 |
| 全量范围 | 在另一个临时目录执行 `--all`，检查五个技能的目标与资源 |
| 冲突保护 | 目标有同名目录或其他链接时停止，不覆盖；相同目标的重复执行不破坏已有链接 |
| 真实触发 | 仅在已获真实安装授权后，检查 Codex 是否发现技能并能显式调用 `$promotion-master` |

临时目录安装只验证文件行为，不等于 Codex 已经扫描或启用该目录。

## 内容行为

| 场景 | 观察点 |
|---|---|
| “先给方向，等我确认” | 给读者、范围和叙事建议、小样与取舍，然后停下 |
| 已确认客户版三问 | 直接完成三问，保留依据与条件，客户正文与制作说明分开 |
| 两版配套 | 同一事实，分别成稿；数字、日期、结论和适配边界一致 |
| 资料不足或保密输入 | 收窄无法支持的主张；不将未获准披露的内容改写成客户卖点 |
| 限定附件、不联网 | 只使用指定材料，缺口说明清楚，不凭记忆补数或宣称外部核验 |

原始材料、实际请求、完整回复及后续修改分别保存。参与者有既往上下文或参与规则维护时，
如实标注；不要把维护者回放称为全新盲测。虚构输入示例见 [examples.md](examples.md)。

## 可选 Word 工具链

选择 Word 后再检查排版依赖：

```bash
bash tools/install_codex.sh --with-word --dest "$promotion_test_dir/skills"
bash tools/selftest.sh
```

需验证全部专项入口时，安装准备与自检均显式加 `--all`。
doctor 必须报告实际缺失项；构建、提取或转换失败不能静默跳过。
渲染后逐页查看中文、表格、图片与分页。无法目视时写明“版式未经代理目视检查”。

脚本通过、内容审阅和真实同事试用是不同证据。macOS 本机与 Linux CI 分别记录实际执行范围；
没有实跑的平台和宿主不宣称通过。测试记录中的私有材料不提交公共仓库。
