## 这轮测试能证明什么

- 两个完整资料场景实际写到最终 Markdown 成品，另有一个资料不足的方向确认场景。
- 设备案例的新旧版使用相同输入与明确任务；均要求核心判断、定位候选、十二问、适配、话术、证据与缺口。两者都写出十二题，不能单凭数量推断新版更好。
- 原始输入在 [设备资料](../../evals/fixtures/service-equipment.md) 和 [债券资料](../../evals/fixtures/short-credit.md)，不同于技能中的成熟示范数据，但仍属于技能示范涉及的两个产品机制，不是对任意行业的泛化验证。
- 执行者可以读取各自技能及其要求的参考，不提供预期终稿或评审期待结论。材料限定为附件、禁止联网，不宣称完成现实数据核验。
- 评审由报告作者之外的代理完成。评审者已有本轮早期规则诊断背景；复用执行代理也有本线程先前上下文，并非全新无历史会话。
- 稿末包含方法版本，实际不满足严格盲法。结果只能作为单次定性比较，不是受控因果实验、成功率或营销转化证据。
- 原始测试稿保留作者交付说明与自评，后续独立结论与修正单独列出。作者自报技能版本或模型名称不是运行环境审计证据；旧稿实际指定来源为 report-skills v1.3.0 的公开源码提交 `2c96b4e`，新稿指定为 Promotion Master `0.1.0-preview.1`。

## 请使用者确认的重点

- 判断是否让你对产品多理解了一层，而非只把材料整理得更长？
- 定位是否既准确又能讲给客户听，候选是否有真正不同的入口？
- 客户最难的问题是否得到直接回答，追问时是否站得住？
- 这两份稿的密度、语气和可用程度是否接近你希望同事交出的材料？

确认成品水准后再正式发布并决定真实安装；本轮不会自动跨过这个验收点。
