# Word 版式：踩过的坑与对策

`scripts/report_lib.js` 已经内置了下面大部分对策；自己写构建脚本或改库时照此检查。

| 现象 | 原因 | 对策 |
|---|---|---|
| 图片被压成一条细线 | 段落行距未显式声明规则，部分渲染器按固定行距处理 | 所有段落的行距都显式设为自动规则；图片段落不设固定行距 |
| 封面大标题行距巨大 | 自动规则下行距值是“行数的 240 分之一”，不是磅值 | 大字号用 260 左右，不要写 700、800 |
| 表格最后一行孤零零掉到下一页 | 表格自然跨页 | 九行以内的小表，除最后一行外全部设置“与下段同页”；长表允许跨页并重复表头 |
| 目录在手机或预览里是空白 | 目录域需要在 Word 里手动更新 | 用手工目录，只列章节标题，不带页码 |
| 页脚“第 N 页”字号不一 | 页码域与文字在同一个文本块里，部分渲染器不继承字号 | 把“第”、页码域、“页”拆成三个文本块，各自设字号 |
| 中文图表出现方框 | 绘图库找不到中文字体 | `chart_style.py` 会按名称在系统里回退（Noto Sans CJK、PingFang、微软雅黑等）；都没有时按 `doctor.py` 的提示安装 |
| 执行摘要多出一两行占掉整页 | 章节强制分页 | 成稿后检查摘要是否两页内；超出就删句子，不要缩字号 |
| 页数超标 | 表格留白与行距偏大、保持同页造成空白 | 先收紧正文行距与表格单元格边距，再考虑删内容 |
| 出现生僻字或错字 | 模型对罕见字不稳定 | 拿不准的字换一种说法；交付前跑 `text_qa.py` |
| 表格列宽错乱 | 只设了表格宽度或只设了单元格宽度 | 表格宽度、列宽数组、单元格宽度三者都设，单位用 DXA |
| 表头或单元格底色变黑 | 底纹类型用了实心 | 底纹类型用 CLEAR，颜色写在 fill |

## 检查流程

1. 构建前先跑 `scripts/structure_qa.py work/report.json`，零 FAIL 再构建；宿主提供 docx 校验脚本（Claude 环境）的话，构建后也跑一遍。
2. 跑 `scripts/render_qa.py`：转 PDF、报告页数、生成缩略图总览。
3. **逐张看总览图**；对新增或复杂的页面用放大参数单独看。
4. 跑 `scripts/text_qa.py` 查残留标记、慎用词和过程性字眼。
5. 任何修改之后重复第 2、3 步；不要凭推测认为版式没问题。

## 页面设置默认值

A4，左右边距 1 英寸，正文 10.5 磅，行距约 1.3 倍，表格字号 8 至 9 磅；中文字体微软雅黑，西文 Arial。标题用深蓝，强调色用一种蓝和一种红，全篇不超过四种颜色。
