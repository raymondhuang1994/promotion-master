# 从证据到有说服力的材料

用于选中的产品分析、定位、创意、问答与营销模块。不强迫行业研究变成销售宣传。
目标是让客户理解产品角色和取舍；允许判断“优势不充分”，不以成交承诺代替判断。

## 1. 营销任务

沿用方向确认卡，填明：受众、现有选择/持仓（未知就标未知）、主要疑虑、
希望改变的认识、渠道、下一步动作。区分“管理层想做多大”与“客户为什么考虑”。
只问会改变产出的缺项，不为填满字段重复问答。

## 2. 事实与主张共用一本底稿

先按 `insight-discovery.md`（研究/定位任务）或当次已确定的研究结论提炼主线，再填主张卡。
主张卡是检验和传递判断的载体，不是把资料重排为“卖点”的机器。
没有形成判断时回到事实中的差别、机制与客户选择，不以形容词补位。

事实 F：原文/数值、来源及定位（文件页码或 URL）、数据日期、口径、直接核验/转引/未核实、
内部使用限制。计算 R：输入 F、公式、单位、日期差异、结果、忽略项。
主张 C 引用 F/R，不重新抄一套数据。短任务可在对话维护，长任务写入 work/。
数据变更时列出受影响的 C 和成品，避免改了正文却留下旧口号与旧问答。

每条核心主张卡记录：

| 字段 | 要回答的事 |
|---|---|
| 客户问题与主张 | 为谁解决哪个疑问？一句话主张是什么？ |
| 认识与选择的变化 | 相比原材料摘要多解释了什么？因此怎样比较或使用才更准确？ |
| 证据与成立机制 | 哪些 F/R 支撑？为什么这些证据能推出结论？哪些只是背景？ |
| 产品承接 | 行业机会通过哪些实际持仓、权重、规则或结构进入产品？ |
| 替代方案 | 相比客户现有选择，增量是什么，代价是什么？ |
| 反证与边界 | 最有力的质疑是什么？何时不成立、何时竞品更合适？ |
| 表达与状态 | 对应方向、标题/解释、可作内部讨论/待补证据/可进入待审稿；不可自称合规批准 |

通常推荐一个主张与少量支撑点，备选保留；数量取决于任务，不为凑数制造发现。

## 3. 防止有数字但没有有效推论

- 产业增长 → 企业收入/利润 → 指数实际敞口 → 价格与费用 → 产品角色 → 客户需要，是不同判断。
  每一步要有机制与范围，不能用资本开支直接推出基金净流入或股价上涨。
- 相对比较必须有双方同口径数据。费用差的解释用相对权重差，不用己方绝对权重；
  贡献（百分点）= 权重差（百分点）× 假设相对表现（百分点）÷ 100。
  缺竞品权重就不能计算相对费差覆盖；静态示例给上下行情景，不冒充完整收益归因。
- 小占比的生动故事不能代表整只产品；全公司业务不能直接当作主题收入。
- 比喻可以增强理解，不能替代证明。“收费”“底座”等不能自动推出垄断、永久定价权或稳定收益。
- 不能从同业规模小唯一推出教育不足；同时考虑需求、渠道、成本、替代品，写明待验证解释。
- “已有 A，再看 B”不自动意味着分散；要检验共同持仓和共同风险因子。

## 4. 先选叙事，再精修

按 direction-confirmation.md 确认方向。精修前读选定主张卡，保留原句记录。
同一主张可以用研究、传播、双层三种表达，不偷偷改变事实或适用范围。
双层组合可含：记忆点标题、解释性副标题、关键证据、口语解释和适用边界。
证据不足时保留创意供内部比较、标明缺口；给可支持的备选，不用免责声明为错误主张兜底。

一句话定位先有准确底稿（目标读者、产品实际角色、比较对象、增量和代价），
再有可传播表达。完整营销报告默认提供三个有实际取舍的候选并推荐一个；
每句注明场景与取舍，允许直白、对比或形象表达，不强制每次创造比喻。
简短传播句可以由副标题补充必要范围，但不能靠解释推翻标题的错误暗示。
证据已支持时清楚给结论，不把已知事实永远写成“有待研究”；证据不支持则明确收窄。

## 5. 同底稿，按需交付

| 交付 | 重点 | 不应混入 |
|---|---|---|
| 管理层研究 | 判断、竞争、证据、选项与行动 | 为宣传效果而掩盖反证 |
| 销售培训包 | 主卖点一页纸、口语解释、关键异议、适配检查 | 无法解释来源的漂亮数字 |
| 客户沟通待审稿 | 指定渠道与长度，主张—证据—边界一致 | 内部策略、客户隐私、未核实的承重论据 |

用户只选一种就不自动生成三套。完整分析也不等于多个格式；
缩短文本时保留使主张成立的关键限定，证据可移到可追溯的来源页，不可失联。
“待审稿”与“已批准对外使用”不同，AI 不替代团队审批。

完整产品推广报告默认串起核心问题、少量核心判断、推荐定位、十二问十二答和一分钟话术。
问答标准见 `toolkit-templates.md`：先直接回应，给决定性依据与条件，最重要异议加追问。
读者只选定位、三问等局部任务时不生成全套；经营目标、渠道和KPI也不自动附加。

## 6. 语义检查（结构脚本不能代替）

逐个核心 C 检查，指出原文位置并给判断，不能只给总分：
1. 换成竞品名字还完全成立吗？若是，可作共性背景，不能称独有优势。
2. 数据真能支持结论吗？有没有单位、基准、时间或比较对象偷换？
3. 客户最强异议回答了吗？让另一位审阅者尽量推翻主张。
4. 看一分钟能复述“给谁、产品角色、为何考虑、最大代价”吗？
5. 原句/偏好是否保留？不同成品的主张、数字、边界是否一致？

阻断交付：关键事实捏造、计算/比较错误、未经核实的承重事实被写成确定结论、
核心主张无证据、用户未确认就越过执行停点、擅改 exact 项。
若任务要求成熟营销成品，判断没有增量解释、定位无法复述或关键问答避而不答，
同样不能按“其他项目得分高”算合格；标记待改并精修。按质量标尺分别报告基础正确与营销质量，
不以空泛评分宣称已有市场转化效果。
