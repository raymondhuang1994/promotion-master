# 配套 Project 的配置要点（摘要）

技能固定“怎么做”，Project 固定“关于什么”。团队共用一个“管理层深度报告”Project 即可；单份报告体量很大、材料很多时，再另开子项目。

**项目指令（可直接粘贴）**
> 使用 promotion-master：先有限预读，推荐完整分析、部分模块或现稿优化，给方向小样和取舍，等我确认再研究成稿。营销材料可选研究型、传播型、双层表达，喜欢的原句记录保留级别。已确认范围不重复问；核心主张被推翻、需要扩大范围或改动保留项时再确认。范例只作方法参考，观点独立；公司口径与公开文件按时点和证据等级核对，有冲突说明，未知内部事实列缺口。真实材料和项目偏好不进入公共技能仓库。

**知识库建议放**：管理层认可的范例报告一到三份；已交付的优秀终稿；公司产品清单与官方费率口径；合规慎用词与对外表述要求；常用数据代码表。
**不要放**：过程稿与旧版本；未脱敏的客户数据；会过期的行情数据。
**维护**：每份报告交付后做一次复盘回写，把新踩的坑与新模板提给技能维护人，更新技能版本。
